## Withheld from memory-efficient load

- **CausalWan** (causal_wan_custom): the checkpoint may require a manual single-file fallback after its Diffusers index load fails; exact collective-safe key discovery is not declared
- **Hunyuanvideo-1.5-Distilled** (hunyuan_video_15_variants): the HunyuanVideo 1.5 distilled checkpoint uses the separate 1.5 wrapper and has not been verified for config-only collective loading
- **Hunyuanvideo-1.5** (hunyuan_video_15_variants): HunyuanVideo 1.5 uses a separate wrapper whose config-only construction and checkpoint layout have not been verified for the standard collective loader
- **Hunyuanvideo-1.5-Sparse** (hunyuan_video_15_variants): the sparse HunyuanVideo 1.5 loader composes base non-block weights with remapped Tencent sparse blocks outside _build_transformer
- **LTX-2.3** (standard_transformer): stage 2 distilled LoRA is applied before a meta transformer would receive its base checkpoint; collective meta loading is withheld until that load order is reordered and verified
- **LTX-2** (standard_transformer): stage 2 distilled LoRA is applied before a meta transformer would receive its base checkpoint; collective meta loading is withheld until that load order is reordered and verified
- **LingBot-Video-Dense** (standard_transformer): shares the MoE runner's composed _build_pipe construction and its own per-block FSDP wrapping, so the same config-only collective load remains unverified for the dense checkpoint
- **LingBot-Video-MoE** (standard_transformer): the pipeline is composed from separately loaded components in _build_pipe rather than through a config-only transformer seam, and the runner shards with LingBot's own per-block FSDP wrapping that ignores minority-dtype fp32 norm and router parameters instead of xDiT's sharding path
- **MiniMax-H3** (standard_transformer): the pipeline is built by ModularPipeline.from_pretrained for a task workflow and its components are loaded afterwards, and fuse_qkv_projections rewrites attention into attn.to_qkv, so live tensor names stop matching checkpoint keys and no collective-safe mapping is declared
- **MiniMax-H3-Ref2VA** (standard_transformer): shares the base MiniMax-H3 modular construction and qkv fusion, and loads its denoiser as transformer_ref, so config-only collective loading is unverified for the reference-to-video workflow as well
- **SD3.5** (sd35_composition): xFuserStableDiffusion3Pipeline is a composition wrapper around a fully loaded Diffusers pipeline and has no config-only transformer construction seam
- **Wan2.2-Distilled-I2V** (distilled_wan_remap): external LightX2V checkpoints support mapped local blockwise loading but not standard distributed collectives

## Components excluded from meta construction

- **Ideogram-4** `text_encoder`: the FP8 checkpoint stores this encoder with the same per-row scales as the transformers, but it is built through AutoModel with trust_remote_code, so its parameter names come from code the manifest cannot read ahead of the load; it is filled eagerly while the two denoisers use the meta path
- **Krea-2-Raw** `text_encoder`: Krea2's Qwen3VL text encoder uses a ROCm-specific float32 Linear runtime patch; exact quantization targets and a compatible quantize-on-load API are not declared
- **Krea-2-Turbo** `text_encoder`: Krea2's Qwen3VL text encoder uses a ROCm-specific float32 Linear runtime patch; exact quantization targets and a compatible quantize-on-load API are not declared
